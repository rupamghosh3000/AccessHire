# AccessHire AI — 3D Specification

## 1. Technology
- Three.js
- React Three Fiber
- @react-three/drei
- Framer Motion for UI motion
- optional GSAP for controlled scroll choreography

## 2. 3D Scenes

### Scene A — Hero Accessibility Network
A clean 3D pathway with nodes:
Discover → Understand → Prepare → Apply

Interaction:
- hover/tap highlights node
- selecting a node updates a nearby 2D information panel

### Scene B — Application Journey
Used in BarrierLens and application preview.
A path contains:
Job → Preview → Form → Review → Submit

Potential barriers appear as labeled markers.

### Scene C — Dashboard Journey
Small low-cost 3D visualization showing:
- saved jobs
- active application
- next step
- accessibility state

## 3. Performance
- lazy load each canvas
- use low-poly geometry
- use instancing for repeated elements
- avoid large textures
- cap pixel ratio
- pause when canvas is not visible
- avoid expensive post-processing
- test low-end laptop/mobile

## 4. Accessibility Fallback

If:
- WebGL unavailable
- reduced motion enabled
- device is low capability
- user disables 3D

replace the canvas with:
- semantic SVG/HTML journey
- static illustration
- accessible list of stages

## 5. Interaction Rules
3D should never contain the only path to:
- search
- apply
- save
- submit
- navigation
- accessibility settings

## 6. Loading
Show a lightweight skeleton/2D placeholder before the 3D scene loads.

## 7. Camera
- no forced rapid camera movement
- no infinite spinning
- use subtle camera movement
- disable automatic camera motion for reduced-motion mode

## 8. Visual Language
Prefer:
- connected nodes
- paths
- portals
- soft depth
- subtle particles

Avoid:
- realistic human avatars
- huge city scenes
- complex environments
- game-like HUDs
